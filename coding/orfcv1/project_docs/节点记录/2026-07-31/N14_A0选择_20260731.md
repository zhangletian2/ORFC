### 两条描述项（不参与判定）

- **匹配配置的代价**：R96 的 A0 就是 s42/λ0.5/ep100，R64 的不是。若强行在两个码率都用匹配配置，
  R64 要多付 282010.26 − 270767.50 = **11242.76（+4.152%）**。协议是「该码率上最强的 ORFC」，
  两个锚点同规则施加，这本身不是不对称。
- **seed 波动**：ep100 三个 seed 的极差在 R64 是 8166（2.9%），在 R96 是 1840（0.87%）。
  R64 的 A0 领先第二名只有 621（0.23%），**小于该锚点的 seed 波动**——A0 在 R64 上是
  「这一族里最强的一个」，不是「显著强于其余」。这一条限制了 N19 里 `D(A2)−D(A0)` 的解释力度：
  它比较的是 v11 与一个具体检查点，不是与 ORFC 的期望性能。

## 2. 旋转空间 MSE 不是任务度量（顺带确认）

R64 的候选表里两列的序**相反**：相对量化误差最低的候选（0.41332）dev 失真排到倒数第三，
而 dev 最优的 A0 量化误差最高（0.44756）。ep300 一族整体是「旋转空间里解释得更少、
下游 tail 失真更低」。本节点不依赖这一点（判据只用 dev 失真），但它复核了一件已知的事：
在旋转空间里最小化 MSE 与在 tail 上最小化失真不是同一个问题。

## 3. W-I5 按实测重述（**这是对权威计划 §4 的一处更正，不是实现细节**）

计划 §4 的 W-I5 写的是 `‖U₀ᵀU₀ − I‖_F ≤ 1e-4`。**没有任何 ORFC 检查点满足它**：

```
R64  A0        6.908e-04        R64 匹配配置   5.052e-03      R64 最差者   1.160e-02
R96  A0        1.401e-03
```

成因不是 v11 的算术，是被热启动的对象本身。ORFC 用 Cayley 参数化 `R = (I−A)⁻¹(I+A)`，
在**精确算术**下对任意反对称 `A` 都严格正交；但 ORFC 自由训练 `A`，`‖A‖_max` 在 R64 达到 **121**，
`I − A` 病态，fp32 solve 丢掉几位。这不是可以「修好」的东西——**修好它就换掉了被比较的基线**。

因此：

1. **A0 按原样评测，不做投影。** 投影后的 codec 是 ORFC 从未产出过的东西，
   「我们超过了 ORFC」就会变成关于一个被我们修过的基线的陈述。
2. **闸门从形式移到后果。** `‖RᵀR−I‖_F` 是外延量，摊到 D 个方向上才是奇异值偏离 1 的
   逐方向 rms。A0 的逐方向值是 **2.16e-05**（R64）/ **4.38e-05**（R96），
   即每个方向被缩放的幅度在 0.005% 以内。新闸门 `ORFC_ORTH_PER_DIRECTION_TOL = 1e-2`
   （每个方向 1% 以内），全部候选通过，包括 1.160e-02 那个（逐方向 3.6e-04）。
3. **`ORTH_TOL = 1e-4` 保持全部效力，但作用在训练漂移上**——按相对初值的增量度量。
   v11 仍然不能把 `U` 训坏。

### 这个决定值多少：直接测了

同一份码本，一次用原样 `R`，一次用它的 QR 投影，dev 同图同分配：

```
R64   投影后 orth 1.61e-05   R 最大位移 4.76e-06   dev −0.61   （−0.0002%）
R96   投影后 orth 2.07e-05   R 最大位移 1.18e-05   dev −1.16   （−0.0005%）
```

非正交性在**判据本身**上值 2e-06 到 5e-06 的相对量——比 `REPLAY_REL_TOL = 8·2⁻²³ ≈ 9.5e-07`
大几倍，比任何一个候选之间的差距（最小 0.23%）小三个数量级。所以「保持原样」这个选择
在数值上是无关紧要的；记录它是为了让**它无关紧要这件事**本身有证据，而不是被假定。
（附带：投影是**略微改善**的方向，所以保持原样也不是在给 A0 放水。）

## 4. npz↔pt 交叉核验的容差同样按实测重标

原先 `1e-5` 是猜的，首次运行即误报。实测（R64 s42 / R96 s42）：

```
‖A‖_max                      1.210e+02   3.069e+01
max|R_pt(fp64) − R_npz|      6.108e-05   1.351e-05     ← 存档值 vs 真值
max|R_pt(fp64) − R_pt(fp32)| 6.273e-05   1.445e-05     ← 重算值 vs 真值
‖ΔR‖_F / ‖R‖_F              1.652e-04   4.570e-05
```

存档的 `R` 与真值的距离，和一次独立 fp32 重算与真值的距离**同量级**：两者都是同一个病态系统的
fp32 解，在 fp32 允许的精度内完全一致。故改为无量纲的相对 Frobenius 闸门 `1e-2`——
是实测底噪的 60 倍，是「装错检查点」（相对偏差 ≈ √2）的百分之一。
决定性的同一性核验仍然在码本上：`array_equal` 逐字节相同，不含任何 solve。

**未设闸的一项**：`.npz` 的 `pmf` 与 `softmax(log_prior)` 差 0.077（R64）/ 0.031（R96）。
量级太大不可能是算术——`pmf` 存的是经验码字使用直方图，不是学到的先验。
v11 本阶段没有码率项，两者都不读；只作 provenance 记录。
