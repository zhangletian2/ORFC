## 1. 这个节点在做什么

在 N14 冻结的 A0 上，把单一码本扩成三模式菜单，并证明**扩完之后的东西在均匀分配下仍然逐比特是 A0**。

| | R64 | R96 |
|---|---|---|
| A0 | `blk20_K4_emb32_bt1024_ws_tau0.5_lr0.001_ep300_n5000_s42` | `blk20_K8_emb32_bt1024_ws_lmbda0.5_tau0.5_lr0.0003_ep100_n5000_s42` |
| 均匀比特 | 2 | 3 |
| 三模式 bits | 1 / **2** / 3 | 2 / **3** / 4 |
| 三模式 K | 2 / **4** / 8 | 4 / **8** / 16 |
| 均匀模式来源 | **copied from A0** | **copied from A0** |
| 侧模式来源 | A0 旋转后 train-fit 上 k-means++/Lloyd(100) | 同左 |
| 训练向量 | 3500 图 / 899,500 向量 | 同左 |

菜单三步循环（`MENU_PERMUTATION_SEED = 20261101`，两锚点同一置换）：
`a^(1)` 全 1；`a^(02)` 置换后前 16 组 mode-0、后 16 组 mode-2；`ā^(02)` 互换。
**名义码率整数守恒**：三条分配的 `nominal_rates` 实测为 `[64,64,64]` / `[96,96,96]`。
**覆盖计数**：`coverage_min = coverage_max = 1` —— 每个 `(g, mode)` 每周期恰好被辅助前向覆盖一次，G3 的机械部分在初始化时即已成立。

## 2. W-I 结果（两锚点，全 PASS）

| 不变量 | R64 | R96 | 判据 |
|---|---|---|---|
| **W-I1** `U_init == R_A0` | `max_abs_delta = 0.0` | `0.0` | 逐元素相同 |
| **W-I2** `codebook_1 == A0` | `max_abs_delta = 0.0` | `0.0` | 逐元素相同 |
| **W-I3** hard 索引逐元素相同（dev-500） | **0 / 4,112,000 cell 不同** | **0 / 4,112,000** | `array_equal` |
| **W-I3** 同上（train-fit 100 图探针） | **0 / 822,400** | **0 / 822,400** | `array_equal` |
| **W-I4** 逐图 tail 失真相对差 | `2.308e-07` | `1.475e-07` | ≤ `9.537e-07` |
| **W-I5** `‖U₀ᵀU₀−I‖_F` | `6.908e-04` | `1.401e-03` | 见 §3 |
| **W-I5** 每方向 | `2.159e-05` | `4.378e-05` | ≤ `1e-2` |
| **W-I6** layer/tail/norm | 20 / `blocks[21:]` / `per_image` | 同左 | 一致 |
| **AUX-SG** `‖∂D_aux/∂U‖` | **0.0（精确）** | **0.0（精确）** | 必须恒零 |

两点值得单独记：

- **W-I3 的实际内容**。A1@0 与 A2@0 是**同一个文件**，两臂的差别从第一次外层事件才出现，所以 W-I3 不是在比两个臂，而是在问：三模式里有两个模式是新拟合的，重建出来的 codec 在均匀分配下还是不是 A0？答案是逐 cell 相同，一个 cell 都没差。
- **AUX-SG 是精确零，不是小量**。辅助支路对 `U` 的梯度范数实测 `0.0`，即 `sg(U)` 的 detach 确实切断了这条路径。辅助项只能校准码本，不能与主支路争夺 `U` 的更新方向 —— 这是 §6.2 的设计前提，现在是实测事实。

W-I4 的两组 dev 均值也一并留档：R64 `A1 = 270767.49771875` / `A0 = 270767.497625`（N14 记录的 `270767.49734375`）；R96 `A1 = 211854.7021875` / `A0 = 211854.70321875`（N14 `211854.70278125`）。三者的散布 ~1e-6 相对，落在 fp32 replay 容差内，符合「参数与索引逐元素相同、只有 tail 归约允许落在容差内」的要求。

## 3. W-I5 按 N14 §3 的重述执行

N14 已经把 W-I5 从「形式」改判为「后果」，本节点沿用：继承自 ORFC 的 `‖U₀ᵀU₀−I‖_F` 只**记录**，闸门放在每方向量 `‖U₀ᵀU₀−I‖_F/√D ≤ 1e-2`；`ORTH_TOL = 1e-4` 保留全部效力，但作用对象是**训练漂移**（相对初值的增量）。

这里出现了一个必须写下来的数值差异：N14 对 R64 匹配配置量到的是 `5.05e-03`，而 N15 里 A0 的实测值是 `6.908e-04`。两者不矛盾 —— **它们不是同一个检查点**。R64 的 A0 是 dev 上最强的那个（`tau0.5_lr0.001_ep300`），不是匹配配置；R96 的 A0 恰好就是匹配配置，其 `1.401e-03` 与 N14 的 `1.40e-03` 一致。也就是说 R64 选出来的 A0 在正交性上恰好比匹配配置好一个数量级，这是选择的副产品，不是本节点做了任何投影。**A0 一律按存储原样使用，未做 QR 投影。**

## 4. 一个必须在 N16 之前写下的混淆（本节点的主要发现）

菜单里的三个模式**训练来历不同**：均匀模式是 ORFC 对着 ORFC 目标训到收敛的，两个侧模式是同一批旋转后特征上的普通 k-means。这不是实现瑕疵，是 §4 W-I2 强制的（均匀模式必须逐比特复制 A0，因此不能重拟合）；但它的后果需要量化。

**旋转空间 MSE（train-fit，899,500 向量）**：

| 锚点 | mode-0 | mode-1（A0 复制） | mode-2 |
|---|---|---|---|
| R64 | K=2 → **393.46** | K=4 → **458.45** | K=8 → 306.64 |
| R96 | K=4 → **329.79** | K=8 → **355.83** | K=16 → 283.59 |

**码字数减半的 down 模式，MSE 反而比均匀模式低。** 这在「A0 码本是这批特征的 MSE 拟合」的假设下不可能发生，所以做了一次事后诊断：同 K 重新 k-means。

| 锚点 | K | A0 码本 MSE | 同 K 新拟合 MSE | 比值 |
|---|---|---|---|---|
| R64 | 4 | 458.45 | **336.50** | **1.362×** |
| R96 | 8 | 355.83 | **298.79** | **1.191×** |

结论：**A0 的码本离旋转空间 MSE 最优点有 19%–36% 的距离**，因为 ORFC 训的是任务失真加率的目标，不是旋转空间 MSE —— 这与 N14 记录的「旋转空间 MSE 不是任务度量」是同一件事的两个侧面（N14 里 R64 相对量化误差最低的候选在 dev 上排倒数第三）。

**对 N16 的约束**：在 step 0 的菜单上做一比特搜索，任何一次交换都同时改变了两件事 —— 比特预算（研究对象）和码本来历（非研究对象）。因此 N16 只能被表述为**「热启动点上外层搜索是否可动」的可行性探针**，不能被表述为非均匀分配有收益的证据。这个混淆要到 N18 才被消除：菜单覆盖辅助项让三个模式对着同一个目标训练，届时 A2 vs A1 才是干净对照。此约束已写进 `bridge.py` 模块文档、`bridge.json` 的 `codebook_provenance_caveat` 字段与 N16 的判定规则本身（eligibility 刻意设成弱条件：只问「搜索是否动了且 dev 没有可测变坏」，不拿这个被混淆的量去筛锚点）。

侧模式**没有**做任务预训练，也不打算补 —— 补了等于给 A2 一个 A1 从未得到的优势，会污染 §8 的 G4。这条不对称是记录下来的设计选择，不是待修的缺陷。

## 5. 实现要点

- `qhard.py` 逐字复用 v10 的数值（`quantise_hard_ste`、`distortion`、`revive_dead_codewords`、`selfcheck`），只新增 v11 需要的辅助支路：`_DetachedRotation` / `_DetachedCodec`（`get_rotation()` 返回 `.detach()`）、`auxiliary_allocation`、`coverage_counts`、`joint_loss`（返回 `main.mean() + β·aux.mean()`，β=1）、`assert_rotation_gradient_free`。
- hard-STE 前向 `z_hat = z_hat + (z - z.detach())` 与硬最近邻**逐比特相同**，没有温度，所以训练损失**就是**终点度量，不存在 soft/hard 落差。
- `init_menu.py` 的两条刻意不对称已写进模块文档：均匀模式复制不重拟合（W-I2 要求 `array_equal`），侧模式因此在 step 0 更弱（§4 已量化）。
- `search.py` / `stats.py` 为薄再导出层，`import` 时断言常量未漂移（§11「不复制第二份搜索器」）。**`stats.py` 不能盲目再导出 v10 的函数**：v10 把 `BOOTSTRAP_SEED = 20261001` 绑成了默认参数，直接再导出会让 v11 用 v10 的种子重采样，而 `config.py` 声称的是 `20261103` —— 预注册种子会变成一句注释。改为直接包 `phase1.unseal` 的基础估计量并显式传 v11 常量，另加 `assert_estimators_are_shared()` 保证两轮仍共用同一实现。
