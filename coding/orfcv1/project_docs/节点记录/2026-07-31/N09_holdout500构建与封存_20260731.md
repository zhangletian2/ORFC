## 1. holdout-500 是什么，为什么可以是它

`features/test/dinov2_vitl14/blk20/` 的 500 张图。它**不是** `phase1/splits.py`
四分法里的任何一集，v8 与 v9 从未读过。`measure-3000` 已在 v9 开封
（`unseal.json` 存在），作为盲测集已经花掉，v10 **不碰它**，只把它当 v9 历史基准引用。

构造路径刻意与另外四个缓存**用同一份代码**：`build_cache.cmd_features`
按升序基名整池 stack，再 `build_cache.cmd_teacher --layer 20 --batch 16`，
与 `stack_features.sh` / `teacher_forward.sh` 当初跑的完全一致。
`v10/build_holdout.py` 只负责选参数与核验，不重写构造逻辑——
第二份实现就是第二个需要维持一致的东西。

## 3. W4：第一版判据是错的量，改写而不是放宽阈值

**首跑失败**：按「逐元素比较 teacher 激活」判，相对偏差 1.827e-6 > 9.537e-7。
诊断（`probe_w4.py`，同一 tail、同一特征、只改比较的图数）：

| 图数 | 整批？ | max&#124;Δ&#124; | 相对 |
|---:|---|---:|---:|
| 96 | 是 | 1.669e-5 | 9.571e-7 |
| 100 | 否 | 3.052e-5 | 1.827e-6 |
| 112 | 是 | 2.003e-5 | 1.119e-6 |
| 500 | 否 | 1.979e-5 | 1.105e-6 |

**整批也超**，所以不是末批形状的问题，是 tail 在 fp32 下真实的运行间不可复现性。

**为什么不能靠调大 `REPLAY_REL_TOL` 通过**：这个 8 ULP 的常数是 v9 在**逐图失真**
（257×1024 项平方和，量级 ~8e5，归约误差大量抵消）上测定并冻结的；
而逐元素比 1.3e8 个激活取 max 是**极值统计**，样本越多越大。
为了让一个下游根本不消费的量通过，去放宽 v9 与 v10 所有失真闸门，是本末倒置。

**改写后的 W4**（用 v10 真正消费的量）：teacher 只通过
\(D_n=\|\mathrm{tail}(\hat x_n)-\mathrm{teacher}_n\|^2\) 进入结果，
所以判据是——重算一遍 teacher，要求**冻结的 v9 R64 codec 在均匀分配下的
逐图硬失真**在缓存 teacher 与重算 teacher 下一致，容差用**原封不动的**
`REPLAY_REL_TOL`。激活的逐元素偏差降级为**记录项**。

同时加一个**阳性对照**证明这道闸门有分辨力：把 teacher 沿图轴 roll 1
（对的 tail、对的层、错的配对），看它偏多少。

```
mean_distortion            685,692.5625
distortion_rel_deviation   1.823e-07     ← 噪声底的 0.19×，W4 通过
tolerance                  9.537e-07
mispaired_control_rel      0.8142        ← 错配对照
control_over_deviation     4.47e+06
activation_max_rel_diff    1.203e-06     ← 记录项，非闸门
```

即真实缺陷（错配）比 fp32 噪声大 **六个半数量级**，没有任何东西能藏在这条带里。
