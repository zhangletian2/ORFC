## 2. 终止时手上确凿的三件事

**（一）N16 的空集是真的，不是实现故障。** 两个锚点各 992 个一比特候选全部劣于均匀，最优候选 −2.88 %（R64，g10→g6）/ −2.53 %（R96，g10→g9），接受 0 次交换。搜索器是 v10 的原件（薄再导出 + 五常量断言），不是第二份实现。dev 那一次验收比的是均匀对均匀，只有 5e-9 的 fp32 归约噪声，不含分配信息。

**（二）空集的成因已被单变量诊断钉死，并且不是 `U`。** 同一张 A0 旋转，只把 mode-1 从「A0 任务训练码本」换成与另两模式同源的 k-means（mode-0/2 逐比特不变），跑完全相同的 992 候选扫描：

| | 改善候选 | 最优增益 |
|---|---|---|
| N16 菜单 | 0/992 · 0/992 | −2.88 % · −2.53 % |
| 同源菜单 | **527/992 · 426/992** | **+3.60 % · +2.55 %** |

所以「ORFC 的 `U` 已经抹平逐组失真谱、吸收了全部非均匀收益」这一解释**被排除**。一比特邻域在 ORFC 的旋转上是否下坡，取决于菜单三模式是否同源。

**（三）同源菜单不是更好的工作点，是对照。** 它的均匀分配任务失真是 A0 的 **3.16×**（R64：852,157 vs 270,001）/ **2.74×**（R96：584,232 vs 213,297），尽管它的旋转空间 MSE 更低。因此 +3.60 % / +2.55 % **不可外推**到任何真实工作点，只能读作「该对照点的邻域是下坡的」。

这同时是「旋转空间 MSE 不是任务度量」的第三次独立复现（N14 的 dev 排名倒数第三、N15 §4 的 1.36×/1.19×、本节点的 3 倍任务失真反转）。

## 3. 留给下一轮的设计输入（本轮唯一的正向产出）

**硬约束（诊断直接给出，不是推测）**：

> 任何从已训练检查点热启动的多模式菜单，**三个模式必须同源**。若均匀模式沿用原检查点的任务训练码本、侧模式用普通 k-means 重拟合，则一比特搜索被码本来历差支配，比特预算从来不是约束项 —— 搜索会在 992 个方向上全部上坡，而这与旋转是否已抹平失真谱无关。

由此，下一轮如果还要走「ORFC 热启动 + 非均匀分配」，**必须先解决初始化的对称性**，而不是先跑搜索。至少三条互斥的路子：

1. **先训后搜**：先只开菜单覆盖辅助项把三模式训到同一目标（v11 §6.2 的 `L = D(U,Θ,m_t) + β·D(sg(U),Θ,a_s)` 已实现于 `qhard.joint_loss`，AUX-SG 实测对 `U` 梯度精确为 0），再开外层搜索。v11 的 N18 本来就是这个设计，只是被 N16 的闸门挡在前面 —— 这条路的代码已经在库里，可以直接复用。
2. **放弃热启动**：像 v9 那样从同源初始化整体训练，代价是失去 ORFC 检查点这个强基线的热启动优势。
3. **改问题**：承认「在给定检查点的一比特邻域内搜索」这个提法本身对热启动不友好，把非均匀性放到别处（例如联合学习阶段而非事后搜索）。

**不可越界的表述**（写给论文稿）：本轮**没有**测到非均匀分配在任何真实工作点上的收益，也**没有**证否它；N16 是一个其自身文档已声明「只能读作可行性探针」的量。v9 的 −1.600 % / −1.227 % 仍然是本项目唯一成立的非均匀结论，其成立范围仍受 `v9-nonuniform-confirmed-20260731` 那四条限制约束。
