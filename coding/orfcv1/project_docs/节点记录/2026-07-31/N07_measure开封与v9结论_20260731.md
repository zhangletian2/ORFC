## 1. 开封协议的执行证据

| 环节 | 证据 |
|---|---|
| 候选先于封条 | `cal_sweep.json` mtime R64 02:49:30.810Z、R96 02:49:41.655Z；封条 02:56:54.959Z。脚本在写封条后**再次**断言两个 mtime 严格早于封条，否则 `INVALID_EXPERIMENT` |
| 只见两个分配 | 每锚点送进 measure 的只有 `[uniform, candidate]` 两行，脚本里没有 argmin、没有扫描 |
| 候选码率重核 | 开封前对 uniform 与 candidate 各重算整数名义码率，= 64 / 96 |
| codec 来源重核 | `frozen.load_checked` 对 `codec_ref.npz` 逐元素相等 + 元数据；`check_layer` 对 measure cache 与 codec 的 feature cache 都核了 layer |
| 一次性 | `unseal.json` 已存在时脚本拒绝再跑（「第二次看 = second look」）。本文件写成后 measure 对 v9 永久关闭 |
| 统计规格先写后跑 | 10 万次重抽、seed 20260731、FWER 0.05、单侧、族 = {R64, R96}，全部在 `config.py` 里、在任何 codec 存在之前就写死 |

**UCB 与 p 值同源**：UCB 取自与 p 值同一条 bootstrap 分布，在 Holm 分配的 α 上取分位，
所以「p < α」与「UCB < 0」是同一句话，不是两个可能打架的判据。

**收益不是均匀分布的**：中位数与均值接近，但两个锚点都有约 10–16% 的图变差，
95% 分位为正。诚实表述是「**在图像总体上稳定降低，但并非逐图一致降低**」，
不能写成「对每张图都更好」。

## 3. cal → measure 的保持率（winner's curse 的实测量级）

| | cal 增益（被选择过） | measure 增益（干净） | 保持率 |
|---|---:|---:|---:|
| R64 | 11,712.94 | **11,246.67** | **96.0%** |
| R96 | 6,648.13 | **6,530.62** | **98.2%** |

选择偏差只吃掉 4.0% / 1.8%。这与 N6 §1 的间隙分析一致：冠军与亚军相差 2,769 / 1,454 倍
噪声底，冠军身份非常稳固，因此「在 cal 上被选中」这件事本身几乎没有夸大它的增益。

**注意这不是普遍规律**：992 个候选里只有 90 / 103 个优于均匀，
若真实效应接近零，同样的 argmin 会产出一个几乎全是偏差的「增益」。
保持率高是**事后观察到的事实**，不能反过来当作「以后可以直接用 cal 值」的许可。

## 4. 这个结论覆盖什么、不覆盖什么

**可以声称**：
- 在 blk20、G=32、d=32、`per_image` 归一化、DINOv2 ViT-L/14 上，
  对 R64（均匀 K4）与 R96（均匀 K8）两个低码率锚点，
  各自的 `(U₀,Θ₀)` 冻结时，**存在**一个同码率非均匀分配严格优于均匀分配，
  幅度约 **1.2–1.6%** 的完整 tail 失真，FWER 0.05 下两点同时显著。
- 该结论用的是**硬最近邻**前向，没有任何代理（Φ̂_J、Φ_sep、Ω、soft 失真）参与判定。
- 候选是**全邻域穷举**（992 点）的精确经验 argmin，不是启发式挑的。

**不可以声称**：
1. **不是 32 组的全局最优**。搜索域只是均匀点的一比特邻域（992 点），
   不是 𝒜_R（R64 下可行分配数远超此数）。真实 **m\*** 只会更好，好多少未知。
2. **不是「联合学习优于 ORFC」**。`U₀` 与码本全程冻结，本轮**没有学习任何东西**。
   联合学习 U/码本/分配是下一步，v9 只是给它证明了「非均匀这条路有东西可拿」。
3. **不是真实码率下的比较**。名义码率相等 ≠ 熵编码后码率相等。
   非均匀分配的符号分布不同，`R_ψ` 未测。**这是进入 BD-rate 声称前必须补的一步**。
4. **不外推到其他层 / 其他码率 / 其他 backbone**。两个锚点的组重要性排序本身就不一致
   （N6 §3：R96 的极端坏 donor g14 在 R64 里并不突出），跨设置照搬没有依据。
5. **多比特转移未测**。一比特邻域的可加性（N6 §3，R² = 0.998）不保证两比特、
   三比特转移仍可加；DP 在更大邻域上的解质量是未验证的。

## 5. 与既有主线的关系

- **v8 的死因被绕开了**：v8 在 M3（菜单单调性）停下，因为它要先证明六档菜单健康，
  而菜单健康性依赖预训练，预训练依赖 τ 和 soft–hard 间隙。v9 把三档菜单的健康性
  **直接交给 992 点完整 D 穷举回答**——如果某档病了，含它的候选自然会输给均匀点。
  N6 测到 89–90% 的一比特转移确实劣于均匀，这正是「菜单不是随便动都好」的实证，
  而它不需要任何单独的闸门。
- **对 P7（φ 凸性 ⇒ 离散反向注水）**：本轮不检验，也不能检验——一比特邻域不够。
  但 N6 §3 的 donor/receiver 边际给了 P7 一个可直接对照的量：
  若 φ 可分且凸，donor 边际应与 receiver 边际近似互为相反数且随组有序，
  实测两者跨度相差 2.8×/4.1× 且方向结构不同。**这是下一步值得算的第一件事**。
- **对统一主线的 Φ+C+N 分解**：本轮没有做分解。收益 1.2–1.6% 究竟落在 Φ 还是 C 上未知。

## 7. 下一步（不在 v9 范围内，供决定）

1. **测非均匀候选的真实熵率 `R_ψ`**——第 4 节第 3 条是当前离「超过 ORFC」最近的缺口。
2. **扩大搜索域**：两比特转移 / DP 在完整 𝒜_R 上求解，检验一比特邻域外还有多少增益。
3. **把 U 放开**：v9 已证明固定 `U₀` 下非均匀有收益；项目目标是联合学习 U/码本/分配，
   现在有了一个干净的、可复现的基线来衡量联合学习到底多拿了多少。
4. **Φ+C+N 归因**：1.2–1.6% 的收益来自哪一项。
