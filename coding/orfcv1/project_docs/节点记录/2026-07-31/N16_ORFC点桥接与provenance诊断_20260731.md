## 1. N16 结果（两锚点，判据 FAIL）

冻结菜单、cal-500 完整 hard 一比特搜索（992 候选 + 基点 = 993 次分配评测），dev-500 一次性验收。

| | R64 | R96 |
|---|---|---|
| A0 | `blk20_K4_emb32_bt1024_ws_tau0.5_lr0.001_ep300_n5000_s42` | `blk20_K8_emb32_bt1024_ws_lmbda0.5_tau0.5_lr0.0003_ep100_n5000_s42` |
| `‖U₀ᵀU₀−I‖_F` | 6.908e-04 | 1.401e-03 |
| cal 基点均值 | 270,001.16 | 213,297.04 |
| **改善候选数** | **0 / 992** | **0 / 992** |
| 最优候选 | g10 → g6 | g10 → g9 |
| 最优候选相对增益 | **−2.8807 %**（即更差） | **−2.5312 %** |
| 最优增益 / 接受阈值 | −3020.6 | −2654.2 |
| 接受交换数 | **0** | **0** |
| 分配轨迹 | 全 1（未动） | 全 1（未动） |
| dev 配对均值 | −0.00141 | −0.00072 |
| dev 相对变化 | −5.19e-09 | −3.39e-09 |
| dev p / Holm α / UCB | 0.01383 / 0.0250 / **−0.0002** | 0.09040 / 0.0500 / **+0.0002** |
| eligible | **否** | **否** |

`--decide` 原样输出：

```
[R64] swaps 0  dev -0.0014 (-0.0000%)  p 0.01383  Holm alpha 0.0250  UCB -0.0002  not eligible
[R96] swaps 0  dev -0.0007 (-0.0000%)  p 0.09040  Holm alpha 0.0500  UCB +0.0002  not eligible
N16 verdict: FAIL  eligible []
v11 ends here; holdout-500 stays sealed (plan section 9).
```

**两条必须写清的读法**：

1. **dev 那两行不含任何关于分配的信息。** 接受 0 次交换 ⇒ 最终分配 = 初始分配 = 全 1，所以 dev 上比的是均匀对均匀。−5e-9 的相对差是 fp32 归约噪声，`p = 0.01383` 只是说这点噪声在 500 图上非零，不是效应。eligibility 之所以是「动了 **且** dev 没变坏」的合取，正是为了让这种情形判否而不是判是。
2. **eligibility 刻意设成弱条件**（只问搜索是否动了），就是因为 §0 的混淆已知；即便如此仍然为空，说明混淆的量级压过了整个一比特邻域。

**这是对 v9 的符号翻转。** v9 在同一个一比特邻域、用它自己的冻结 `(U₀, Θ₀)`（三模式同源）量到 R64 −1.600 % / R96 −1.227 % 且双双通过 Holm。同样的搜索器、同样的 cal 规模、同样的判据，换到 ORFC 工作点上得到 +2.88 % / +2.53 % 的反向结果。两者唯一的系统性差别就是菜单来历。

## 2. 为什么必须做诊断

0/992 有两种解释，指向相反的下一步：

- **(P) 来历**：mode-1 是 ORFC 对着任务目标训到收敛的，mode-0/2 是旋转后特征上的普通 k-means。一次交换把两组同时移出好码本、移进弱码本，**来历差被付了两次**，比特预算从来不是约束项。若成立，N16 对非均匀分配零信息，修复就是设计里已有的 N18 菜单覆盖辅助项。
- **(U) 旋转**：ORFC 的 `U` 可能真的把逐组失真谱抹平了，没有哪一组便宜到可以让出一个比特。若成立，非均匀假设在这个工作点上本身有麻烦。

`diagnose_provenance.py` 只拆这一个变量：**同一张 A0 旋转**，三个模式**全部用同一套 k-means++/Lloyd 拟合**（mode-0/2 用与 `init_menu` 相同的逐模式种子偏移 ⇒ 与 N16 逐比特相同，**只有 mode-1 变**），跑完全相同的 992 候选 cal 扫描。

## 3. 诊断结果：(P) 确证

| | R64 | R96 |
|---|---|---|
| 改善候选数（N16 菜单，mode-1 任务训练） | **0 / 992** | **0 / 992** |
| 改善候选数（三模式同源 k-means） | **527 / 992** | **426 / 992** |
| 最优相对增益（N16） | −2.8807 % | −2.5312 % |
| 最优相对增益（同源） | **+3.5974 %** | **+2.5545 %** |
| 最优交换（同源） | g2 → g7 | g27 → g3 |

**结论：N16 的 0/992 完全由 mode-1 的码本来历造成，与 ORFC 的旋转无关。** 同一张 `U` 上，把唯一的不对称去掉，一比特邻域从「992 个方向全部上坡」变成「一半以上方向下坡」。假设 (U) 被排除：不能说 ORFC 的 `U` 已经吸收了非均匀收益。

顺带复核了 N15 §4 的比值：mode-1 的 A0 码本 / 同 K 新拟合 = **1.374×**（R64）、**1.194×**（R96），与 N15 事后诊断的 1.362× / 1.191× 一致（微小差异来自本节点用 `CODEBOOK_SEED + 1` 的种子偏移，N15 那次是独立重拟合）。

### 3.1 诊断本身的边界（不可越界）

**同源菜单不是一个更好的工作点，是一个对照。** 它的 cal 任务失真显著更差：

| | 均匀分配 cal 均值（N16 菜单） | 同上（同源菜单） | 比值 |
|---|---|---|---|
| R64 | 270,001 | **852,157** | **3.16×** |
| R96 | 213,297 | **584,232** | **2.74×** |

也就是说：把 mode-1 换成旋转空间 MSE 更低的 k-means 码本，任务失真反而差 3 倍 —— 这是 N14「旋转空间 MSE 不是任务度量」的第三次独立复现。

因此诊断能支持的命题**只有一条**：

> 一比特邻域在 ORFC 的 `U` 上是否下坡，取决于菜单三模式是否同源；N16 的空集是初始化的性质，不是旋转的性质。

它**不**支持：非均匀分配在一个好的工作点上有收益（同源点差 3 倍，不是候选）；也**不**支持任何关于 +3.60 % / +2.55 % 幅度可迁移到 N18 的推断。真正干净的对照只能是 N18 的 A2 vs A1 —— 那里两个臂共享逐元素相同的热启动，且菜单覆盖辅助项已让三个模式对着同一个目标训练。

## 5. 实现要点

- `search.py` 是 v10 搜索器的薄再导出层，`import` 时断言 `S_OUTER_MAX / EPS_ACCEPT_MULT / REPLAY_REL_TOL / EVAL_IMAGE_BATCH / EVAL_PAIR_BUDGET` 五个常量与 v10 一致（五项全部匹配，故再导出安全）—— §11「不复制第二份搜索器」。
- **`stats.py` 不能同样处理**。v10 把 `BOOTSTRAP_SEED = 20261001` 绑成了函数默认参数，盲目再导出会让 v11 用 v10 的种子重采样，而 `config.py` 声称 `20261103`。改为直接包 `phase1.unseal` 的基础估计量并显式传 v11 常量，另加 `assert_estimators_are_shared()`。本节点 dev 统计的 `bootstrap_seed` 落盘为 `20261103`，与预注册一致。
- **本节点没有 W9 重放不变量**，`bridge.py` 文档已写明理由：v11 在 ORFC 的旋转上搜索，v9 的 cal 矩阵不是关于它的预测，硬比是拿两个不同网络对表。
- 诊断模块写死 `not_a_selection` 字段：它构造的 codec 不能成为 A0/A1/A2，且只读 cal（N16 搜索已见过的集合），不消耗任何验收效力。
