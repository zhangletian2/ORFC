## 1. 协议与它为什么这么定

| 项 | 取值 | 理由 |
|---|---|---|
| 搜索集 | cal-500 | 与 v9 穷举同一集，W9 才能逐格比对 |
| 验收集 | dev-500 | Stage B **唯一**用途，此后不再读 |
| 起点 | 均匀 `m = 1·𝟙` | 用户要求「从均匀点出发」 |
| 邻域 | 全部合法一比特交换 | 首轮 992 个候选（+基点 = 993 行） |
| 接受判据 | 增益 > `10 × REPLAY_REL_TOL × D` | 噪声底的 10 倍，防止把 fp32 抖动当收益 |
| 预算 | `S_OUTER_MAX = 8` 次接受 | 两锚点都提前自停（§3），预算没用满 |
| 统计 | 配对 bootstrap 100,000 次，seed 20261001，单侧，Holm 跨两锚点 FWER=.05 | 与 v9 同估计量、v10 自己的种子 |

`holdout-500` 与 `measure-3000` 在本节点**完全未被读取**。

## 2. W9：v10 的第一轮就是 v9 的那张表

第一轮的 993×500 矩阵与 v9 落盘的 `cal_distortion.npy` 逐格比：

```
R64   max 相对偏差 5.247e-07  = 噪声底的 0.55×   argmin idx 751 = down g24 → up g7
R96   max 相对偏差 5.760e-07  = 噪声底的 0.60×   argmin       = down g15 → up g26
```

两个 argmin 都**正是 v9 冻结的候选**。这不是巧合而是构造出来的：
`search.legal_swaps` 在起点为均匀时，会在运行时断言自己的枚举与
`engine.swap_candidates` 逐行相等，否则直接 `INVALID_EXPERIMENT` ——
否则「993 行」形状对得上、含义对不上，W9 就成了一个看起来通过的空检查。

`verify --stage bridge` 不采信 Stage B 自报的偏差，而是从落盘矩阵与 v9 的参考
矩阵**重新算一遍**（0.55× / 0.60×，与自报一致）。两份实现存在的意义是让它们有机会不一致。

## 3. 搜索轨迹：两个锚点都提前自停

```
R64  step 1  down g24 → up g7   gain 11713.01  (1.6529%)  = 17332.1× 噪声底  ACCEPT
     step 2  down g11 → up g2   gain  4461.60  (0.6402%)  =  6712.9×        ACCEPT
     step 3  down g2  → up g27  gain    −9.06  (−0.0013%) =    −13.7×        停止

R96  step 1  down g15 → up g26  gain  6648.20  (1.2340%)  = 12939.5×        ACCEPT
     step 2  down g19 → up g7   gain  1897.65  (0.3566%)  =  3739.6×        ACCEPT
     step 3  down g13 → up g27  gain  1202.69  (0.2268%)  =  2378.5×        ACCEPT
     step 4  down g9  → up g2   gain   186.59  (0.0353%)  =   369.9×        ACCEPT
     step 5  down g10 → up g24  gain    −7.31  (−0.0014%) =    −14.5×        停止
```

两点值得记下：

- **8 次预算都没用满**（R64 用 2 次、R96 用 4 次），是被接受判据自己停住的，
  不是被预算截断的。所以「再多搜几步会不会更好」在 cal 上已经被回答了：不会。
- 增益逐步衰减近似几何级数（R96：6648 → 1898 → 1203 → 187），
  且**首步就是 v9 的那一步**。一比特邻域里的收益高度集中在第一步。

邻域随搜索缩小，实测每轮行数 **993 / 932 / 873 / 816 / 761**，
与 `(G−k)² − (G−2k) + 1` 在 k=0..4 处**精确吻合**（三模式菜单在两端没有余量：
已到底的组不能再降、已到顶的组不能再升）。这条实测后来被写回
`profile.outer_forward_equivalents`，替换掉原先「首轮 993、其后一律 932」的错误模型 ——
原模型会把 A2 外层预算高估 18%，从而给 A3 多发步数。

## 4. W8 措辞修正（公开记录）

计划 §5 要求 A1 与 A2 在前 `T_outer` 步「**逐比特同态**」。**这一条在本栈上不可达**，
而且 v9 已经量过原因：两次相同的 tail 调用因归约顺序不可复现，会差到 1 个 fp32 ULP，
几百步之后初始的 1 ULP 会放大。写一条每次运行都必须豁免的不变量，
比写一条真正被执行的弱不变量更糟。

因此 W8 改写为只断言**确实精确可查**的部分：

- 相同的初始张量（`frozen.load_checked` 逐元素比对，W5）；
- 相同的 batch 索引流（落盘后 `np.array_equal`，不是「相信两个随机数发生器」）；
- 相同的超参（逐键比对 `profile.json` 的消费值）；
- 第一个 block 内相同的分配（外层事件在 block **之后**才触发）；
- 外加 step-1 损失落在 `REPLAY_REL_TOL` 之内。

此后的发散是算术，不是协议差异。修正已写进 `train.py` 与 `verify.py` 的模块文档字符串，
性质与 N9 的 W4 改写相同：**改的是判据写在哪个量上，不是判据的松紧**。
