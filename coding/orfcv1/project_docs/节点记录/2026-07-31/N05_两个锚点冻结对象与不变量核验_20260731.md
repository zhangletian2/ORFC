## 1. 两个冻结对象

共同规格：blk20（`blocks[21:]`）、G=32、d=32、`per_image` 归一化、
cache `features_train_blk20_n4500_ss20260730.npy`、TF32 全程关闭、
OPQ 交替 30 轮（内层 10 次 Lloyd，k-means++，seed 0）、
三档码本各自独立 k-means++ + 100 次 Lloyd（`seed = 0 + mode`）。

| | **R64** | **R96** |
|---|---|---|
| 均匀档 | K=4（2 bit/组） | K=8（3 bit/组） |
| 名义码率 | 64 bit/token | 96 bit/token |
| 菜单 (down/uniform/up) | K2 / K4 / K8 | K4 / K8 / K16 |
| 码本形状 | (32,2,32) (32,4,32) (32,8,32) | (32,4,32) (32,8,32) (32,16,32) |
| OPQ warm-up K | 4（= 本锚点自己的均匀档） | 8（同左） |
| OPQ mse 首→末 | 306.688 → **288.205** | 289.354 → **263.672** |
| `orth_error_float64`（build 时） | 1.149e-6 | 1.152e-6 |
| 三档 rotated mse | 338.879 / 288.611 / 271.294 | 309.785 / 264.740 / 247.799 |
| 死码字比例（max / mean） | **0 / 0**（三档全部） | **0 / 0**（三档全部） |
| 构建耗时 | 137.8 s | 138.9 s |

**两个锚点各有自己的 `U_0`**：OPQ warm-up 在本锚点的均匀 K 上跑，
不共用、也不从对方迁移。这是 v9 §2 的规定——`U_0` 与被检验的菜单必须同一来源，
否则「非均匀是否有用」会混入「`U_0` 是为哪个 K 优化的」。

**构造纪律（`codec.json` 里三个写死的 `False`）**：
`reused_opq_codebooks=False`（warm-up 的 K 档码本没有直接当初始码本）、
`reused_orfc_codebooks=False`、`task_tail_pretraining=False`。
不做任何 task-tail / soft 预训练的理由见 N4 §2；这里只记录它在产物元数据里可核。

**菜单单调性（描述，不设闸门）**：两个锚点的 rotated mse 都随 K 严格下降
（R64 338.9 > 288.6 > 271.3；R96 309.8 > 264.7 > 247.8）。这只是**旋转域重构 mse**，
不是 v8 M3 所测的完整 tail 失真，**两者不得互相引用**。v9 不设 M3 闸门——
它把「菜单是否健康」直接交给 992 点穷举的完整 D 去回答。

## 3. 重放噪声底（后面所有「增益」的尺子）

| | R64 | R96 |
|---|---|---|
| 逐图失真量级 | 706,428.3 | 541,136.5 |
| 该量级下 1 个 fp32 ULP | 0.0625 | 0.0625 |
| 同一分配 8 次重放的最大相对偏差 | **1.769e-7** | **2.310e-7** |
| 两轮完全独立重放之间 | 1.769e-7 | 2.310e-7 |
| 8 次重放的**集合均值**相对散布 | 8.85e-8 | **0.0**（逐位相同） |
| 闸门 `REPLAY_REL_TOL` | 9.537e-7 | 9.537e-7 |

即实测占用了闸门的 19% / 24%。N4 §3.2 把闸门定为 8 ULP 是在 toy codec 上先写后跑的，
两个正式锚点都落在带内且有 4–5 倍余量，说明这个常数没有被结果反向选择。

R96 的集合均值散布**恰好为 0**：500 图上重放两次得到逐位相同的均值，
只有逐图层面有 1 ULP 抖动且相互抵消。R64 的 8.85e-8 同样是 ULP 级。
