## 0. 本节点的协议修正（**须原文保留**）

> v8 原协议允许 dev 早停先于退火完成，导致最终温度依赖实际停止步数。观察到档位相关
> soft–hard 偏差后，在 measure 开封和正式消融之前，将「完成预注册退火」加入早停必要条件；
> 旧 checkpoint 仅保留为诊断，不参与选择或验收。

执行规则（用户 2026-07-31 裁定，按「公开的协议修正」而非「两个 checkpoint 择优」处理）：

1. 旧 checkpoint 保留，标记为「v8 初始化诊断产物」，**不进入正式消融**；
2. 协议更新为：只有当 \(\tau_0=0.05\) 已达到、且 hard-dev 连续 \(k=3\) 次稳定时才允许停止，
   即**退火完成是早停的必要条件**；
3. 从相同 \(U_0\)、K-means 码本重新运行一次，固定完成 \(0.2\to0.05\) 的退火，
   再执行原 hard-dev 判停；
4. **不在新旧 checkpoint 之间选择**；修正版唯一产物成为新的 I14 共享初始化；
5. 只在新 checkpoint 上运行 M1–M5 菜单审计；
6. soft–hard 差继续逐轮报告，但**不再用于挑 checkpoint**。正式 S2 中若明显恶化，
   只判定该 run 的代理失效并停止，**不在同一 run 内临时修改温度**。

退火horizon 取 \(S_{\max}/2=10{,}000\) 步 —— 一条**按规则给定的整数分数**，
刻意**不取**诊断 run 实际收敛的 4,000 步，以保证此处没有任何常数由观测结果反推。
修正已写入 `phase1/config.py` 的 `TAU_ANNEAL_STEPS` 注释块（先写后跑）。

## 1. 执行内容与产物

| 步骤 | 规格（§4.1.1 / §4.2 冻结） | 产物 |
|---|---|---|
| OPQ warm-up | train-core 4,000；\(K=64\)；30 次交替 × 10 次 Lloyd；k-means++；seed 0 | `init.pt` 中的 \(U_0\) |
| 六档独立 K-means | 在 \(U_0\) 旋转后的特征上，六档**各自** k-means++ + 100 次 Lloyd，**不复用 warm-up 的 K=64 码本** | `init.pt` 的六组 `codebooks` |
| \(\Phi_{\rm sep}\) 拟合图集 | \(n_{\rm fit}=500\) 个 train-core basename，一次抽定 | `phi_sep_fit_names.txt` |
| 六档均衡预训练 | \(U_0\) 冻结，只更新六档码本；损失=完整 soft tail 失真；train-core 训练、dev-500 判停 | `pretrain.pt` / `pretrain.json` |

**正交性**：\(\|U_0^\top U_0-I\|_F\) 在 float64 算术下评估（对实际落盘的 fp32 矩阵）。
fp32 算术自身在 \(D=1024\) 处的地板约 \(1.3\times10^{-5}\)，已高于计划阈值 \(10^{-5}\)，
故只改「读取该值所用的算术」，**冻结常数不变**。

**两处对既有代码的蓄意偏离**（均已在模块 docstring 记录）：
- `batched_kmeans` 用随机数据点播种，计划规定 k-means++ → 按计划实现，
  因为随机播种明显更易产生 M2 拒绝的近重复质心；
- `p1_fixed_rate.command_prepare` 从整个 4,500 行 cache 抽 OPQ 图像（含 500 张 cal）→
  改为只读 train-core，否则初始化泄漏验收集。

## 2. 两个先于运行发现并修掉的缺陷

**(a) 数据顺序缺陷（推理发现，运行前修复）**。原实现用步长为 batch 的连续窗口取图，
而模式按 `mode = step % 6` 轮转。两个循环同步推进 ⇒ \(\gcd(\text{blocks},6)\) 个剩余类
使每档只见到 train-core 的固定一部分：**更新次数相等但数据不等**，
恰好抵消「均衡预训练」的目的。改为每轮重新取种子化随机排列（`Shuffler`）。

**(b) \(U_0\) 冻结的断言化**。每步断言 `rotation.grad is None`，
运行结束断言 `torch.equal(rotation.detach(), reference_u)`。不依赖「requires_grad=False 应该够了」。

## 3. 两个由 dev-500 定下的超参（计划允许在 dev 上选）

### 3.1 \(\tau_0\)：计划说「沿用现有退火曲线」，但现有曲线有两条且相差 50×

`allocation_train.py` 是 0.01→0.01，`orfc/run_soft_pq.py` 是 0.5→0.005，
且 `_quantise` 确认两者除的是同一个平方距离代价 ⇒ 分歧是实质性的，不是量纲问题。
历史上不重要，因为 `SoftPQ` 是**直通**（前向恒为硬）；而 §4.1.1 冻结的是**真正的松弛**，
\(\tau\) 因此决定前向。`phase1/tau_probe.py` 在 dev-500 上实测：

| \(\tau_0\) | effective_k (3..8 bit) | max\|rel gap\| | 档间跨度 |
|---|---|---|---|
| 1.00 | 2.9 … 19.9 | 15.43% | 8.96 pp |
| 0.50 | 2.0 … 5.3 | 3.38% | 2.27 pp |
| **0.20** | 1.4 … 1.8 | **0.55%** | 0.46 pp |
| **0.05** | 1.1 … 1.2 | **0.28%** | 0.10 pp |
| 0.01 | 1.0 … 1.0 | 0.06% | 0.03 pp |

档位倾斜是**结构性**的：最近邻—次近邻代价间隙从 3-bit 到 8-bit 下降 20.36→0.93（22×），
而 \(\tau_m=\tau_0 b_{\rm ref}/b_m\) 同区间只降 1.33× ⇒
**逐档缩放系统性欠补偿**，大 \(\tau_0\) 下 8-bit 档承受 3× 于 3-bit 档的松弛偏置，
会把分配比较系统性推向低比特档。\(\tau_0=0.01\) 是相反的病：effective_k = 1.02，
指派梯度通道已死，冻结的「soft relaxation 而非 STE」将成空文。

**冻结**：几何退火 \(0.2\to0.05\)。整条轨迹留在档位中性的 ≤0.55% 带内，
保留真实指派梯度，且 §4.1 要求的审计间隙随退火收缩（0.55%→0.28%）。

### 3.2 学习率：1,500 步 dev 扫描

平均逐档相对下降（对 k-means 初始化）：3e-4 → 26.4%、1e-3 → 32.5%、**3e-3 → 36.2%**、
6e-3 → 36.1%、1e-2 → 33.8%。3e-3 与 6e-3 在总量上打平，但**高 K 档在 3e-3 以上失稳**：
1e-2 下 8-bit 的 dev 失真在 1,000 步后回升（164,079 → 169,680），6e-3 有同样但轻微的回头。
取 3e-3 —— 保持六档全部单调的最大学习率，而均衡预训练的判停规则（六档同时 <1%）正需要这一点。

其余：`PRETRAIN_BATCH = 16`（`bench_train` 实测吞吐在 16–192 之间平坦 ⇒ 这是优化动力学选择，
不是吞吐选择）、`PRETRAIN_EVAL_EVERY = 250`。

## 4. 修正前后的实测对比

| | 诊断 run（`pretrain_diagnostic.*`） | **修正 run（`pretrain.*`，正式 I14）** |
|---|---|---|
| 停止步数 | 4,000 / 20,000 | **10,750 / 20,000** |
| 停止时 \(\tau_0\) | 0.152（退火未完成） | **0.05（`anneal_complete = True`）** |
| soft–hard 逐档相对差 | −4.06% … −6.91% | **−1.21% … −2.24%** |
| 档间跨度 | 2.85 pp | **1.03 pp** |
| dev 3-bit 硬失真 | 380,301 | **370,212** |

诊断 run 的成因由「在训练后 checkpoint 上重跑 \(\tau\) 探针」分离：
在**匹配的** \(\tau_0=0.2\) 下，训练后码本的间隙已比 k-means 初始化大 **~10×**
（码本漂移进了松弛），**截断退火**再贡献约 **3×**。

修正 run 的 −1.21%…−2.24% 与 \(\tau\) 探针在 \(\tau_0=0.05\) 处的预测（−1.5%…−2.5%）一致；
并且修正 run 在**六档全部**更低（3-bit 370,212 vs 380,301）——**降低松弛偏置没有付出失真代价**。

最终 dev 硬失真（3→8 bit）：370,212 / 284,727 / 215,315 / 182,854 / 164,022 / 149,935，
`dev_hard_monotone_in_K = True`，`balanced = True`（六档更新次数极差 ≤ 1）。
