# N27 隔离坐标块优化前置验收与正式启动

## 方法合同

1. 固定当前分配与码本，只更新正交表示 $U$。
2. 固定 $U$，由单组代价表和精确预算 Top-K DP 生成候选。
3. 当前分配与候选分配使用相同数据和相同步数独立适配码本；候选分支中 $U$ 冻结，未使用码本冻结。
4. 在独立 select 集上选择完整目标最低的分支；当前分配胜出时保留其等颍适配后码本。

实现冻结在远程 `dev@9126598`。候选阶段冻结 $U$ 时保留主阶段 $U$ 的 Adam 状态，避免人为重置动量。

## 前置验收

路径：`results/dinov2_vitl14/phase1/v27/v27_preflight_20260806T1640Z`。

- $U$-only：独立 report 目标从 373052.8 降至 193670.8；码本漂移为 0。
- 分支隔离：所有候选的 $U$ 漂移为 0，未选码本漂移为 0，所选码本漂移大于 0。
- 适配步数：$L\in\{1,4,16\}$ 选出完全相同的非均匀分配，且独立 report 目标均改善。
- 候选召回：在 992 个一次交换邻域中构造 64 候选审计池，Top-8 DP 同时召回 select 和 report 的最优候选，两者 winner 一致。
- 精确名义码率、hard parity 和正交误差均通过。

## 正式运行

`RUN_ID=v27_block_full_20260806`，GPU 3/4 为 R64/R96 块坐标优化，GPU 6/7 为等步数固定均匀 $U$-only 对照。100 epoch，外层周期 1000 步，Top-K=8，独立适配步数 $L=4$，cal/select/report 分离。

本方法对固定 select 目标给出接受步的单调性；不声称得到全局 oracle。最终结论需使用冻结 checkpoint 在未参与选择的数据上比较 Tail MSE 与下游任务。

## 正式结果

四个运行均完成 15600 步，无 Traceback/OOM；hard parity 相对误差为
$1.26\times10^{-7}$--$2.52\times10^{-7}$，正交误差约 $2.1\times10^{-5}$。

| 锚点 | 方法 | report Tail MSE | report 目标 | 最终分配 |
|---|---|---:|---:|---|
| R64 | 均匀 $U$-only | 326597.3 | 178196.4 | 均匀 |
| R64 | 块优化 | 326493.2 | 178138.7 | 均匀 |
| R96 | 均匀 $U$-only | 248251.3 | 146679.5 | 均匀 |
| R96 | 块优化 | 248070.7 | 146596.1 | 均匀 |

两个块优化臂的 15 次外层事件均由等额适配后的当前均匀分配胜出，未接受任何交换。候选分支中 $U$ 和未使用码本的最大漂移均为 0，因此该结果不是参数泄漏造成。

在 validation 中未参与 cal/select/report 的剩余 240 张图像上，对每个冻结 codec 枚举 992 个精确码率两组转移。R64/R96 的均匀与块优化 codec 均为局部最优：最好邻居的 Tail MSE 仍分别高 1797--3227，完整目标高 868--1686。因此 Top-K 并未遗漏一个在当前冻结 codec 下可立即改善的两组转移。

结论：先针对当前分配充分优化 $U$，再冻结 $U$ 比较候选，会使当前分配获得表示侧先发优势。实验严格验证了该块坐标实现，但未获得非均匀改进；不能由此推出均匀分配对“每个分配分别重新优化 $U$ 与码本”的 oracle 全局最优。

## incumbent bias 直接验证

首次联合分支实验发现两个合同错误：内层反复拟合 cal-64，且为 $U$ 新建空状态 Adam。在已收敛 checkpoint 上，当前分配仅适配 2 步即使 report 目标从 178k 恶化到 191k，因此该次比较无效。

修复后：候选适配使用 train-fit 512，cal/select/report 仅用于候选构造、选择和报告；每个分支继承完全相同的父 $U$-Adam 动量与二阶矩，码本使用独立优化器。实现冻结于 `dev@f2bc548`。

路径：`results/dinov2_vitl14/phase1/v27/v27_incumbent_bias_check_20260806`。四臂均先使用同一训练流执行 1000 个 $U$-only 步，再分支联合适配 $U$ 与所用码本。

| 锚点 | 分支步数 | select 目标改善 | report 目标改善 | report Tail MSE 改善 | 选中转移 |
|---|---:|---:|---:|---:|---|
| R64 | 64 | 523.9 | 332.0 | 454.9 | g14: 2b$\to$1b, g18: 2b$\to$3b |
| R64 | 256 | 1189.1 | 943.0 | 1679.3 | 同上 |
| R96 | 64 | 451.3 | 164.2 | 298.8 | g11: 3b$\to$2b, g18: 3b$\to$4b |
| R96 | 256 | 490.7 | 351.9 | 691.2 | 同上 |

$L=64$ 与 $L=256$ 在两个码率点均选中相同的非均匀转移，且 select/report 同方向。所有分支都记录 `u_optimizer_state_reused=true`，未使用码本漂移为 0，hard parity 与正交误差通过。

因此 incumbent bias 获得直接支持：冻结针对当前分配训练的 $U$ 会拒绝非均匀候选；允许各候选在等额、状态对齐的条件下联合适配 $U$ 与码本后，两个码率点均出现可复现的非均匀改善。该结果证明局部方法信号，仍不等于全局 oracle 证明。

## 修正后完整训练

`RUN_ID=v27_jointbranch_full_20260806`。GPU 3/4 分别运行 R64/R96 的三分支非均匀竞争；GPU 6/7 运行匹配的当前分配单分支对照。四臂均为 15600 主步、每 1000 步一次外层事件、$L=64$、train-fit 512，并继承父 $U$-Adam 状态。方法臂与对照臂的保留路径更新次数相同，唯一差别是是否允许两个非均匀候选参与竞争。

四臂均完成，无 Traceback/OOM，hard parity 与正交约束通过。R64 方法臂在 1000 步接受一次转移（g8: 2b$\to$1b，g18: 2b$\to$3b）；R96 在 1000 步接受 g11: 3b$\to$2b、g18: 3b$\to$4b，在 5000 步再接受 g15: 3b$\to$2b、g7: 3b$\to$4b。R96 第二次转移的 select 目标改善 227.6，但同步 report 反向 41.9，属于边界决策。
