# N22：V22 确定性 DP 完整训练结果与 Exit

日期：2026-08-06

## 实验合同

- DINOv2 ViT-L/14 `blk20/R64`；
- 从 V21 的 ORFC-Adam 多档 K-means 初始 codec 出发；
- 100 epoch，15,600 步，batch 32；
- 内层使用当前单一硬分配更新 (U)、被选码本和 prior；
- 每 250 步构造局部组–档位代价表，精确预算 DP 输出 top-8，用完整 hard tail ECVQ 目标验收；
- calibration/selection/report 分别使用 64/64/128 张互不重叠图像；report 不参与选择。

远端结果：`results/dinov2_vitl14/phase1/v22/v22_dp_periodic_full_20260806/R64`。冻结源码：`dev` commit `a525a87`。

## 结果

| 指标 | V22 | V21 |
|---|---:|---:|
| 同一 val-500 Tail MSE | 301,111 | **296,848** |
| 同一 val-500 ECVQ 目标 | 165,560 | **163,616** |
| 交叉熵码率（bit/token） | **58.385** | 59.112 |

V22 比 V21 快 6.45 倍，显存峰值为 2.13 GiB，吞吐为 401 images/s。但 Tail MSE 高 1.44%，完整 ECVQ 目标高 1.19%。按预注册 exit，本轮不执行分类和分割评测。

训练自身审计通过：

- hard-parity 相对误差 `2.06e-7`；
- 正交误差增量 `2.02e-5`；
- 最终激活组–档位均获得 15,600 步梯度；
- 激活码本最小参数漂移 0.614；
- 2/4/8 码字档的 dead-centroid 比例分别为 1.56%/1.56%/1.17%，无严重坍缩。

## 失败的直接原因

共执行 63 次外层分配事件，只有起点 DP 分配被接受。后续 62 次中，完整 selection 目标始终选择当前分配，最终分配与起点 DP 解相同。

因果链为：

1. 内层只训练当前分配所使用的码本；
2. 当前码本持续改善，未选档位停留在初始状态；
3. 后续 DP 比较的是“已充分训练的当前码本”与“陈旧候选码本”；
4. 因此分配步在第一次选择后被锁死。

这不是 REINFORCE 方差、DP 求解错误、正交更新失败或 centroid collapse。它是多档候选参数与单一共享 (U) 之间的块坐标可比性问题。

## 理论定位

V22 取消了公平损失和策略熵对最终目标的偏置；当分配固定后，内层直接优化该分配的 (J(\mathbf m,U,\Theta_{\mathbf m}))。外层分配仍未近似

\[
\min_{\mathbf m}\min_{U,\Theta_{\mathbf m}}J(\mathbf m,U,\Theta_{\mathbf m}),
\]

因为候选分配在比较前没有对其专属码本做内层适配。因此 V22 解决了低方差与高效分配求解，没有解决 oracle 中的“候选参数充分优化后再比较”。

## 下一步方法设计

保留精确预算 DP 与完整目标验收，将梯度路由拆成两个块：

1. **主分配块**：只用当前硬分配的完整 tail 目标更新 (U) 和已选码本；
2. **候选适配块**：冻结/停梯度 (U) 和其他码本，对局部单组替换的候选码本和 prior 做少量任务感知内层更新；
3. 用适配后的代价表进行 DP top-K 与完整目标验收。

这种非对称梯度路由使候选码本保持可比，同时避免 strict-fair 将多个候选分配的梯度混入共享 (U)。计算上只适配局部组–档位或 DP top-K，不对全部分配重训。

可并行评估结构共享方向：用 Multiscale Quantization/Extended RaBitQ 式嵌套或残差码本代替完全独立档位，使不同 bit 档共享已训练参数。

### Exit

- 若候选适配后外层能在长程训练中继续接受真实改善的分配，且同图 Tail MSE 优于 V21，再进入下游评测；
- 若候选适配仍无法改变分配，则局部代价 + DP 只适合初始分配，不足以实现长程联合优化；
- 若嵌套码本显著限制最终失真，不用 RaBitQ 的结构化边界替代任务感知码本。
